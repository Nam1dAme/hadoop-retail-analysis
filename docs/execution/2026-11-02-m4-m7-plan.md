# M4—M7 实施与界面设计计划

继续基于 UBA-DOC-1.0.0。源文件入口为项目内 `var/data/UserBehavior.csv`。本次推进模型、预测发布、服务界面及规模/恢复验收；阶段状态以真实执行证据为准。

## 界面设计

使用 frontend-design 技能；以旧项目实际 Streamlit 版本的 `app/assets/theme.css`、`components.py`、`charts.py` 为视觉依据。旧项目还存在绿色静态 demo，本次采用实际应用的蓝色风格。

色彩：文字 `#1D2B45`，主色 `#3159D6`，辅助 `#16838B`，提示 `#B66A16`，背景 `#F2F5FA`，白色内容区 `#FFFFFF`。字体沿用旧项目本地 IBM Plex Sans / Noto Sans SC 子集及原许可，不请求外部 CDN。

布局：白色固定侧栏、浅蓝灰主区域、左对齐标题及版本上下文、克制的指标带、宽窄搭配的图表面板。保留原项目键盘焦点、窄屏折叠与减少动画支持；不采用新概念图的深色侧栏。统计数量、时间窗口和来源状态承担视觉重点，不增加装饰性海报区。

七页对应冻结02：行为总览、商品与类目、用户活跃、行为预测、模型实验、数据质量与任务、版本与方法。视图只读取发布结果，未发布、无结果与依赖失败分别展示；不生成随机指标、不补造商品名称或收入字段。

## 开发顺序与验证

1. M4：三模型、全局精确指标、验证选参及测试封存、epoch恢复、FP32 CPU/CUDA对照、完整样本训练与资源测量。先手算/过拟合测试，再正式运行。
2. M5：沿用选定权重进行未来评分，分批入库，校验同批次完整性，原子发布、回滚与恢复。
3. M6：实现只读API和七页工作台；沿用原项目视觉资产，独立实现新业务，检查真实版本与空态、分页、权限、桌面和窄屏。
4. M7：补齐确定性规模阶梯、临时空间峰值、API负载和隔离恢复，交付运行手册及逐项证据。不把尚未运行的门禁标为通过。

新迁移004初次执行在最后的benchmark表遇到precision保留字错误；审计前三张新表结构及空表状态后，引用该字段、创建缺失表并登记正确摘要。恢复证据保留于`var/production/model-migration-recovery.json`，既有批次与产物未删除。
