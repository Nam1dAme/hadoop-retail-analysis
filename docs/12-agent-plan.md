## 阶段计划

| 阶段 | 工作与依赖 | 退出条件 |
|---|---|---|
| M0 证据与环境 | 阅读本基线；全量profile、来源说明补证、GPU/内存/宿主盘、依赖解析锁、独立配置 | G-ENV；T01/T03画像证据；观察期标签覆盖确认；硬件失败如实记录，可继续不依赖部分 |
| M1 工程与数据 | 新目录模块、控制库、来源登记、HDFS归档、J01/J02、质量门禁；依赖M0配置 | T01—T03、幂等和故障单测通过；原项目未改写 |
| M2 Hadoop分析 | J03/J04、分析表、区间UV/复访、画像报告；依赖M1 | T04—T06；全量真实YARN和守恒，不只抽样 |
| M3 时间样本 | J05/J06、分片导出、normalization、split封存；依赖M1 | T07/T08，人工样例与全量样本数、正例率、排除量一致 |
| M4 模型与CUDA | CONSTANT/LOGISTIC/GRU、候选训练、验证选择、TEST封存、CPU/GPU对照；依赖M3与GPU门禁 | T09—T13；保存实际设备证据、模型及资源报告 |
| M5 预测与发布 | FORECAST、结果装载、原子release、恢复；依赖M2/M4 | T14/T15/T18，发布版本内容完整、回滚不混版 |
| M6 服务与页面 | 08全部接口、02七页、报告与权限；可先用标记fixture开发，正式验收依赖M5 | T16/T19，真实release贯通；移除演示随机值 |
| M7 规模与交付 | 100万/1000万/全量、性能优化、完整运行手册、验收报告 | T17/T20及所有门禁，NOT_RUN为0；未达标不得把目标改小结项 |

不按天数虚构工期；阶段以证据退出。性能实验应从M1起逐步积累，M7汇总而非最后才发现容量问题。允许在M2、M3实现顺序间调整，不改变依赖与最终范围。

## 新项目目录职责（未来创建）

`ingest/`来源与解析适配；`jobs/`Java MR；`orchestration/`调度/恢复/清单；`ml/`特征消费、模型、评价、推断；`service/`API；`app/`页面；`migrations/`新库迁移；`config/`非敏感参数及锁；`tests/`分层测试；`scripts/`运行/验收工具；`var/`本地缓存和日志不入版本管理；`docs/execution/`证据。

可选择性迁入旧项目的hash、心跳、存储、原子发布、只读服务和测试方式；旧schema、UCI来源约束、2011切分、订单/金额/RFM/购物篮/推荐矩阵不迁入。不可直接复制旧var、密钥、数据库、HDFS根或训练产物。每个迁入文件做业务耦合审查，最终以新契约为准，不要求保持原API兼容。

## 每阶段交接

交接记录：完成需求、实际文件/提交、测试命令与结果、真实/合成数据标识、资源峰值、失败及未决事项、下一阶段输入产物hash。阶段成功不能只写“代码完成”；必须有适用门禁证据。模型训练日志应保留实际步数与样本数，不用伪造曲线。

实现中发现冻结文档错误可提出修订，记录影响并统一更新专项和追踪表；用户明确改变目标时优先执行用户意图。不要为了通过测试自行降低全量范围、删除CUDA、将深度学习替换成只有线性模型，或给不存在的字段填常量假装兼容。
