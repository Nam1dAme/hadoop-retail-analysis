# 01 需求分析与产品范围

UBA-DOC-1.0.0 / FROZEN。

## 用户与问题

面向研究者和数据分析者：观察行为规模与节律、类目及商品热度、用户活跃与复访，评价购买行为预测是否有用；面向开发维护者：追踪来源、质量、Hadoop任务、训练资源和发布版本。数据是已抽样的历史用户日志，不代表全站人群或当前经营趋势。

核心预测问题：在锚点t之前48小时至少有一条合法窗口内行为的用户，未来24小时是否至少出现一次buy。负标签仅表示该数据集观察窗口内未记录buy，不表示永久不购买或真实拒绝。预测分数是模型估计，未经校准不宣传为准确购买概率。

## 必做功能

| ID | 需求及完成定义 |
|---|---|
| FR-01 | 流式导入唯一CSV、哈希归档、幂等注册、来源追踪和全量画像 |
| FR-02 | 五字段校验、异常隔离、日期范围标记、重复候选审计及数量守恒 |
| FR-03 | 真实YARN业务作业生成日/小时行为量、精确UV、商品/类目排行 |
| FR-04 | 用户日活跃、观察期首次出现用户、次日复访率和浏览用户购买比例 |
| FR-05 | 严格时间样本，48h特征、24h标签、TRAIN/VALIDATION/TEST隔离 |
| FR-06 | CONSTANT、LOGISTIC与GRU三种模型对照；GRU必须PyTorch/CUDA训练 |
| FR-07 | 单GPU资源测量、可恢复训练、CPU/GPU对照及真实性能报告 |
| FR-08 | TEST回溯预测及观察期结束后未来一天批量评分，清楚区分有/无标签 |
| FR-09 | 七页只读工作台和版本固定API，不在HTTP请求内训练 |
| FR-10 | 不可变发布、原子current切换、回滚、备份及隔离恢复 |
| FR-11 | 样本/模型/指标/运行证据可追溯，输出机器可读报告 |

不做：GMV、订单数、客单价、退款、国家分析、RFM金额、会话真值、曝光CTR、商品推荐、实时流计算、在线训练、多GPU或多机训练。日内浏览购买比例不是因果或顺序漏斗。无商品名称和类目名称时仅显示ID。

## 非功能需求与量化门禁

| ID | 冻结目标 |
|---|---|
| NF-01 | 正式分析扫描完整源文件；不得以抽样替代全量，记录实际行数 |
| NF-02 | 单次重任务互斥；系统MemAvailable低于1 GiB持续30秒停止启动新阶段并受控终止当前重任务；不依赖持续Swap支撑吞吐 |
| NF-03 | GRU GPU allocated峰值≤6 GiB、reserved峰值≤6.5 GiB；单进程训练RSS≤3 GiB；设备总占用另测 |
| NF-04 | 完整源文件首次处理至分析结果及样本准备≤12小时；选定GRU一次正式训练含验证≤8小时；全量未来评分≤2小时；均在09冻结资源配置下实测，不是已达标事实 |
| NF-05 | 10并发、预热后持续5分钟的聚合/分页API，p95≤2秒、HTTP错误率<1%；冷启动另报；GPU训练期间不承诺同一SLA |
| NF-06 | 整数精确、浮点公式误差≤1e-6；故障恢复不重复计数、不暴露半成品 |
| NF-07 | 仅本机访问、最小数据库权限、无凭据入库/日志/版本管理 |
| NF-08 | 100万、1000万、全量阶梯规模均记录耗时、内存、磁盘、Shuffle与倾斜；不承诺超出实测规模 |

NF-04失败必须记录并优化，或按00变更时限；不能直接标通过。模型不优于简单基线仍可完成工程验收，但必须展示失败结果并让服务选择遵守07。

## 已采用的业务默认值

分析窗口2017-11-25至2017-12-04（右端不含），北京时间；不删除重复候选；48h活跃用户为预测人群；按下一日任意buy建标签；首期离线批量预测，无在线个体干预。这些是本次设计选择，不声称用户此前逐项确认。将来改变窗口、目标或去重政策按00修订。
