# 13 决策记录、迁移边界与风险

UBA-DOC-1.0.0 / FROZEN。

## 已冻结决策

| ADR | 决定及依据 | 代价 |
|---|---|---|
| A01 | Hadoop HDFS/YARN/Java MR承担核心分析与样本构建，满足用户必须基于Hadoop的要求 | 多阶段落盘与Java实现成本 |
| A02 | 预测未来24h是否记录购买行为，取代原商品推荐 | 不能回答购买何种商品、金额或订单数 |
| A03 | 固定48h历史、128事件GRU加14维统计，单卡PyTorch/CUDA | 短序列丢失更早事件顺序，但完整48h计数保留 |
| A04 | 不用用户/商品embedding，类别固定哈希 | 避免巨大参数表，牺牲商品身份与细粒度类目区分，hash碰撞须披露 |
| A05 | 按日时间切分，不随机拆事件；验证选参，测试封存 | 观察期短、测试仅一天，结果不能外推长期稳定性 |
| A06 | 不做FULLFIT，未来评分沿用评估checkpoint | 模型较旧但评价与服务权重一致，无再训练泄漏歧义 |
| A07 | 三基线都实现，服务选择由验证结果决定 | GRU可能不胜出；仍必须完成真实GPU训练 |
| A08 | 重复候选保留、异常窗口隔离、原始不可变 | 同秒重复可能影响频次，但避免把合法重复事件删掉 |
| A09 | 单机重任务串行、流式分片、无全量Python交互字典 | 吞吐受单机限制，换取可控RAM |
| A10 | MariaDB只存结果，Web只读离线快照 | 无在线即时预测和任意原始事件检索 |
| A11 | 原项目独立保留，新项目独立库/命名空间/端口 | 需要额外空间，不提供旧销售API兼容 |

## 容量与证据等级

已验证源码事实：旧ingest绑定XLSX/UCI；旧ml固定2011窗口；TrainingData.load全量history字典；ALS local[2]及collect因子；评分遍历用户×商品；YARN配置3GiB/4vcores、Reducer限制1—4。它们证明迁移风险结构存在，不证明新数据已经OOM。

已测文件字节与可见RAM见15。尚未验证：完整行数/基数/时间异常率、实际shuffle峰值、GRU吞吐与显存、宿主物理空闲、CUDA可访问性、新架构全量耗时。不得以“有Hadoop”推导已能横向扩展或已支持十亿行。

## 风险处理

| 风险 | 触发/监测 | 处理与完成约束 |
|---|---|---|
| 主机RAM不足 | MemAvailable/RSS/Swap、容器失败 | 串行、mmap、减microbatch；仍失败需用户调整硬件，不能绕过全量验收 |
| 显存不足或桌面抢占 | allocated/reserved/整卡空闲、OOM | 预检与固定降batch阶梯；不降低目标或CPU冒充 |
| VHDX宿主空间不足 | 两侧空闲和写峰值 | 先验证实际宿主卷；停新任务；不能依据虚拟879GiB承诺容量 |
| 热点用户拖慢Reducer | max/median任务时长、每用户事件数 | 有界状态、分区数和样本压力测试；语义需跨用户拆分时另行设计，不随意截原始事件 |
| 标签观测不完整 | 来源说明、每日计数、时间范围 | 阻止正式标签；不可将缺测日当无购买 |
| 行为强不平衡 | 各split正例率/PR曲线 | AP与LogLoss而非仅准确率；无负采样改变评价总体 |
| 短期时间分布变化 | 每日率、cohort分项 | 如实报告仅此样本窗口，不声称全站/长期泛化 |
| hash碰撞和序列截断 | hash桶占用/碰撞统计、截断样本比例 | 报告并保留baseline；增加容量属于模型版本变更 |
| GPU不加速小模型 | FP32公平对照与正式AMP吞吐 | 接受实测更慢，不能伪造speedup |
| 单机单副本故障 | 备份完整性与恢复演练 | 独立备份，明确没有HA |

## 后续可由用户改变的业务选择

当前冻结默认见01；若需要不同预测周期、商品级预测、推荐、实时更新、十亿级目标、在线API或扩大时间范围，需新需求与基线变更。当前不把这些问题悬置成实现阻塞，也不冒称用户已经确认。硬件测量和官方来源补证是执行门禁，不是待定业务语义。
